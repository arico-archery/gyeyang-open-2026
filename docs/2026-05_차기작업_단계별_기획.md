## 1. 첫 번째 의사결정 (사용자 입력 필요)

다음 세 가지는 운영 방향과 직결되어 있어 작업 전 사용자 결정을 받아야 합니다.

### Q1. 메인 사이트 전환 시점은?

옵션 A: **즉시 (5월 말~6월)** — 메인을 빠르게 "2027 곧 공개" 형태로 전환, 2026은 `/archive/2026`에 이관
옵션 B: **2027 정보 확정 후 (가을~겨울)** — 현재 메인 유지, archive 페이지만 먼저 채움
옵션 C (권장): **절충** — 메인 페이지 상단에 작은 "2027 안내" 배너 추가, 2026 콘텐츠는 그대로 유지

→ **권장: C**. 검색 유입을 잃지 않으면서 차기 대회 관심도 유지

### Q2. 2026 데이터를 어떻게 보존?

현재 사이트는 ianseo 토너먼트 28161에 의존하고 있어, ianseo가 페이지를 내리거나 변경하면 영향을 받습니다.

옵션 A: 현재 그대로 유지 — ianseo가 안정적이라는 가정
옵션 B (권장): **이번에 한 번 스냅샷** — 선수 명단·점수·결과를 정적 JSON으로 저장해 영구 보존

→ **권장: B**. 작업량은 작고 (1~2시간), 데이터 안정성은 크게 향상

### Q3. 운영 인수인계 범위는?

옵션 A: 본 라운드까지만 — 매뉴얼 없이 종료
옵션 B: 기본 매뉴얼만 — 사진 업로드, 공지 작성 정도
옵션 C (권장): **정식 운영 매뉴얼** — 사진·공지·푸시·관리자 권한·트러블슈팅 일체

→ **권장: C**. 차기 대회 운영진이 바뀌더라도 인수인계 가능한 수준

이 세 가지 결정 후 아래 단계를 순서대로 진행합니다.

## 2. 단계별 작업 (Staged Plan)

### STAGE 1 — 대회 종료 정리 (5월 말, 1주차)
**목표**: 종료된 대회의 콘텐츠·데이터를 안정화

#### 1-1. 2026 결과 데이터 스냅샷 (4시간)
- ianseo 28161에서 선수 명단·예선 결과·결승 결과·상위 입상자 한 번 수집
- `src/lib/data/results-2026.json`에 저장 (참고: 이미 `bib-mapping.json` 패턴)
- `/api/participants` 라우트를 폴백 가능하게 변경 — ianseo 응답 실패 시 정적 JSON 사용
- 효과: ianseo가 페이지를 내려도 사이트는 계속 동작

#### 1-2. `/archive/2026` 페이지 신설 (3시간)
- 현재 `/archive/2026`은 ianseo Details 페이지로 리디렉트 → 자체 페이지로 교체
- 구성:
  - 대회 개요 (일자, 장소, 참가국·인원 통계)
  - 메달리스트 (개인·단체 각 종목)
  - 전체 결과 표 (페이지네이션)
  - 사진 하이라이트 (SmugMug에서 10~20장)
  - 대회 비디오 (YouTube 임베드)
  - 「전체 사진 보기」 · 「ianseo 원본」 링크
- 기존 `/archive/2025`와 디자인 통일 (이미 그쪽 패턴 있음)

#### 1-3. SmugMug 사진 보강 (사용자 액션)
- 사진작가 6일치 사진을 일자별 앨범으로 정리
  - `1 Day` (5/13), `2 Day` (5/14), ..., `6 Day` (5/18)
- 메달리스트·하이라이트 사진을 별도 앨범 `Medalists`로 모아 archive 페이지에 노출
- 워터마크 없는 원본 사진작가에게 요청 (선택)

#### 1-4. 콘텐츠 정비 (2시간)
- 종료 후 의미가 사라진 문구 정리
  - 「참가 신청」 페이지 → "신청 마감되었습니다. 결과는 archive에서 확인하세요" 안내
  - 「비자 지원」 → "2026 대회 종료. 다음 대회 정보는 추후 공개됩니다"
  - 「숙소」 「렌터카」 → 동일한 톤
- 또는 메뉴에서 「참가 안내」 그룹을 임시로 숨기고 archive로만 접근 가능하게

### STAGE 2 — 운영 정리 & 인수인계 (6월 초, 2주차)
**목표**: 차기 운영자가 매뉴얼만 보고 운영 가능한 상태로

#### 2-1. 정식 운영 매뉴얼 작성 (4시간)
- `docs/2026_운영매뉴얼.md` 단일 문서로 통합
- 챕터:
  1. 사이트 구조 개요 (Vercel · Next.js · Supabase · SmugMug 흐름)
  2. 도메인·SSL 관리 (Vercel)
  3. 환경변수 일람 (어디에 무엇이 있는지)
  4. 공지사항 작성 (Supabase admin UI)
  5. 푸시 알림 발송 (공지 작성 시 체크박스)
  6. 사진 업로드 (SmugMug, 일자별)
  7. 캐시 새로고침 (`/app/admin`)
  8. 관리자 권한 부여
  9. 자주 묻는 질문 (이미 작성된 SmugMug 매뉴얼 흡수)
- 워드 문서로도 함께 출력 (`docs/2026_운영매뉴얼.docx`)

#### 2-2. 푸시 알림 End-to-End 테스트 (1시간)
- 테스트 계정으로 PWA 설치 → 알림 허용 → 공지 작성 → 푸시 수신 확인
- 410/404 cleanup 로직 동작 확인 (구독 만료된 디바이스 자동 정리)
- 운영 매뉴얼에 스크린샷 포함

#### 2-3. Supabase 정리 (1시간)
- `registrations`, `inquiries` 테이블 — 대회 종료 후 실제 데이터 백업
- 익명화/축약 옵션 검토 (개인정보 보존 기간 정책)
- `attendance` 등 시즌 종료 데이터의 archive 정책 정리

#### 2-4. 비용·계정 점검 (30분)
- Vercel 사용량 · Supabase 사용량 한 번 점검
- 다음 대회까지 1년간 비용 추정
- 결제 정보·만료일 확인

## 6. 기술 부채 메모 (당장은 아니지만 잊지 말 것)

- `next.config.ts`의 `images: { unoptimized: true }` — Next.js Image optimizer를 우회 중. 외부 이미지가 많아 일단 유지하지만, 추후 점검
- `arico-staff-app`의 VAPID 평문 키 — 별도 저장소이므로 본 라운드 밖
- 일부 i18n 키가 SCHEDULE_DATA 등에 영문 하드코딩으로 남아 있음 — 영향 작아 후순위
- 모바일 사파리 PWA 푸시 권한 흐름 — 한 번 직접 테스트 필요 (iOS 16.4+)
